# EpiFORESS Analysis Pipeline

This folder contains the eight sequential analysis scripts, from simulation-based development through internal validation and independent external validation. It is organized for review and reproducibility. It is not a claim that every script has been executed successfully: the R runtime and the required source data/model artifacts must be available to complete end-to-end verification.

## Pipeline map

| Order | Script | Purpose | Main output / role |
|---:|---|---|---|
| 01 | `01_empirical_characterization_simulation.R` | Characterize disease-level surveillance patterns and generate simulated series with controlled surveillance artifacts. | Simulation workbook and simulation metadata. |
| 02 | `02_feature_extraction.R` | Extract the pre-forecast predictors and produce a feature dictionary/modeling table. | `EpiFORESS_feature_extraction_outputs.xlsx` and companion CSVs. |
| 03 | `03_forecasting_experiment.R` | Evaluate candidate forecasting methods with rolling-origin evaluation. | `EpiFORESS_Forecasting_Results.xlsx`. |
| 04 | `04_forecast_readiness_labeling.R` | Join features to forecast outcomes and create readiness labels. | `EpiFORESS_Forecast_Results.xlsx`. |
| 05 | `05_forecast_readiness_modeling.R` | Train and compare statistical/ML readiness models, choose a hybrid score, and save fitted artifacts. | `EpiFORESS_Modeling_Results.xlsx` and `Saved_Models/`. |
| 06 | `06_leave_one_disease_out_validation.R` | Test generalization to a held-out disease using a disease-grouped validation design. | LODO validation workbook and diagnostics. |
| 07 | `07_empirical_validation.R` | Evaluate the deployed EpiFORESS scoring workflow against empirical disease surveillance series and observed forecast performance. | Empirical-validation workbook, plots, and RDS outputs. |
| 08 | `08_external_validation_project_tycho.R` | Independently assess transportability using Project Tycho Level 1 data, retaining disease-by-location-by-location-type strata. | Project Tycho external-validation workbook, plots, and RDS outputs. |

## Recommended folder layout

Keep this `R/` folder as a subfolder inside the main project directory. The scripts use `EPIFORESS_PROJECT_DIR` as the project root and expect input data, generated workbooks, saved models, and the deployed scoring app to be located relative to that root.

```text
EpiFORESS-project/
├── R/
│   ├── 01_empirical_characterization_simulation.R
│   ├── 02_feature_extraction.R
│   ├── 03_forecasting_experiment.R
│   ├── 04_forecast_readiness_labeling.R
│   ├── 05_forecast_readiness_modeling.R
│   ├── 06_leave_one_disease_out_validation.R
│   ├── 07_empirical_validation.R
│   └── 08_external_validation_project_tycho.R
├── External_Validation_Seed.xlsx
├── Raw_Diseases.xlsx
├── Disease_Seeded_MC_Simulation_REFINED.xlsx       # generated by script 01
├── EpiFORESS_feature_extraction_outputs.xlsx        # generated by script 02
├── EpiFORESS_Forecasting_Results.xlsx               # generated by script 03
├── EpiFORESS_Forecast_Results.xlsx                  # generated by script 04
├── EpiFORESS_Modeling_Results.xlsx                  # generated by script 05

│   └── ProjectTycho_Level1_v1.0.0.csv

```

Not every input is required for every script. Scripts 01–05 form the simulation/model-development path; scripts 06–08 are validation stages. The Project Tycho data, model artifacts, and app are **not included** in this code-only subfolder and must be supplied separately under their applicable terms.

## Setup

1. Install a current version of R and the packages listed at the beginning of each script. Several scripts install missing packages automatically; for a controlled competition submission, install dependencies in advance and record the R/package versions.
2. Set the environment variable `EPIFORESS_PROJECT_DIR` to the directory containing the project inputs and `Saved_Models/`, or launch R with that directory as the working directory.
3. Confirm the exact source workbook names and worksheet names match the configured values in each script.
4. Run the scripts in numeric order for development. Run scripts 06, 07, and 08 only after the saved model artifacts and required external/empirical inputs are available.
5. Preserve the generated workbooks and validation outputs as evidence. Do not manually edit model outputs before the analysis is finalized.

Example in R:

```r
Sys.setenv(EPIFORESS_PROJECT_DIR = "D:/path/to/EpiFORESS-project")
setwd(file.path(Sys.getenv("EPIFORESS_PROJECT_DIR"), "R"))
source("01_empirical_characterization_simulation.R")
```

The environment variable must point to the **project root**, not to the `R/` subfolder.

## Key methodological conventions

- **Forecast-readiness outcome:** scripts 04–08 use `Best MASE < 1.00` as the primary binary criterion, with `Best MASE < 0.50` retained as a stricter sensitivity criterion where implemented. Confirm this threshold choice against the final registered thesis/protocol before freezing results.
- **Pre-forecast predictors:** predictors used for readiness classification must be computed only from data available at the screening time. Forecast outcomes and future observations must not enter feature construction or preprocessing.
- **Leakage prevention:** imputation, scaling, feature selection, threshold tuning, and model selection must be learned within training/resampling partitions. The test set must remain untouched until final evaluation.
- **Validation hierarchy:** LODO tests transfer to an unseen disease; empirical validation assesses the scoring system against the designated empirical disease series; Project Tycho is the final external validation and evaluates geographic strata without pooling counts across locations.
- **Dependence:** observations sharing a disease or location, and repeated windows from the same series, are not independent. Interpret uncertainty estimates in light of the clustering strategy used in the validation scripts.
- **Score interpretation:** the EpiFORESS score is a continuous readiness gradient. Descriptive bands are summaries, not proof that the score is a calibrated probability or a clinical/public-health guarantee.
- **Failed fits and missingness:** retain error/status fields and eligibility counts. Do not silently convert missing surveillance reports to zero or exclude failed series without reporting exclusions.

## Reproducibility and reporting checklist

Before submitting results:

- [ ] Record R version, package versions, random seeds, and operating system.
- [ ] Archive the exact input datasets and their source/license information.
- [ ] Verify row counts, join keys, duplicate keys, missingness, and exclusions after every stage.
- [ ] Confirm the 49-feature schema is identical between training and scoring and that all preprocessing comes from training data.
- [ ] Verify the primary threshold and sensitivity threshold are described consistently in the manuscript, tables, figures, and scripts.
- [ ] Confirm the hybrid weights, calibration model, selected models, and scoring function are the same in model development and deployed validation.
- [ ] Report sample sizes at every validation stage, confidence intervals, unsuccessful model fits, and all sensitivity analyses.
- [ ] Do not describe external validation as successful until script 08 has run successfully and its results have been reviewed.
- [ ] Re-run from a clean project copy and confirm the outputs can be regenerated.

## Important limitations

These scripts are supplied as a cleaned and organized research-code pipeline. They have **not** all been executed end-to-end in an R environment as part of this packaging step. Static cleanup and path normalization do not establish runtime correctness, statistical validity, or external validity. Validate the scripts against the exact datasets and fitted objects before using their outputs in a paper, presentation, or competition submission.

The Project Tycho source is external data. Check the current Project Tycho access conditions, citation requirements, data dictionary, geographic coding, and temporal coverage before redistribution or publication. Do not bundle restricted data or private model artifacts in a public submission unless permitted.
